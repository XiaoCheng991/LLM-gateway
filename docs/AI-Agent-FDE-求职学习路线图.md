# AI Agent + FDE 求职学习路线图（12 周可执行版）

> 定位：全栈开发（Java/Spring/微服务/数据工程）背景 → 转型 AI Agent 应用开发 + FDE 交付能力
> 更新：2026-10-14 ｜ 依据：2026 年 9–10 月 AI Agent 与 FDE 岗位真实 JD 调研

---

## 一、先把 FDE 掰清楚（本次调研最大收获）

**FDE ≠ 前端工程师。** F 是 Forward，不是 Frontend。全称 **Forward Deployed Engineer（前线部署工程师）**，2026 年 AI 圈招聘需求暴涨、年薪可达百万级的"最火岗位"，OpenAI、Anthropic、Palantir 都在招。

一句话概括这个角色：**带着 AI 模型，住进客户公司，把客户的问题交付成真实可用、能上线、有人用的系统的人。**

### FDE 的职责闭环（为什么它难）
不是"写代码交差"的工程师，也不只是"交完方案就走"的顾问。FDE 要对**发现 → 范围 → 实现 → 评估 → 采用**全程负责：

| 环节 | 具体做什么 |
|---|---|
| 发现 | 跟着客户真实工作走一遍，找出真正被卡住、反复返工的那一步 |
| 范围 | 用一页纸写清：用户/触发点/输入输出/数据边界/成功指标/不做什么/失败交给谁 |
| 实现 | 做一个**完整可用的切片**（全栈原型 + 认证 + 权限 + 日志 + 转人工路径） |
| 评估 | 建评估集（边界案例/缺失资料/应拒答请求），定义"好/可接受/不安全" |
| 采用 | 小范围发布，盯真实使用、绕开率、更正率，能回退能转人工 |

### FDE 需要的核心能力
1. **工程基本功**（底座）：Python/TypeScript/Java、SQL、云部署、API、可观测性、定位故障
2. **客户发现**：把模糊的"想要 AI"问成可观察的流程
3. **AI 交付判断**：理解检索质量、结构化输出、工具权限、提示注入、时延、token 成本、人工复核、异常处理；判断哪里用确定性软件、哪里接受概率性输出
4. **清晰写作**：范围说明、决策记录、评估计划、发布清单——让交付动起来
5. **全栈能力**：能自己从后端到界面把切片做通

> **对你（小橙）的定位意义**：FDE 最值钱的不是单一技术深度，而是"能把用户流程 + 技术系统 + 上线证据连起来"。你的**全栈 + 微服务 + 数据工程 + 供应链业务认知**恰好是 FDE 的强匹配底子。你的 Java 是加分项，但要补 Python 生态 + AI 应用层。

## 二、AI Agent 岗位细分（2026 年市场实况）

市场把 Agent 赛道分成两大方向、四类岗位（来自 2026 金三银四企业招聘需求调研）：

| 岗位 | 门槛 | 必学核心 | 适合谁 |
|---|---|---|---|
| **AI Agent 应用开发岗** | 最低，校招需求占 70%+ | Python、LLM API、LangChain/LangGraph、RAG、Tool Calling/MCP、ReAct | ✅ 你（本/转岗首选） |
| 多智能体解决方案岗 | 中 | 应用开发基础 + 业务方案 + 系统集成 + 交付 | ✅ 你的业务/数据背景加分 |
| Agent 核心研发岗 | 高，硕士优先 | 算法、Transformer 底层、分布式 | ✗ 与你的方向偏离 |
| Agent Infra 研发岗 | 高 | Rust/C++、分布式、向量检索引擎 | ✗ 偏离 |

**结论**：你要走的是 **「AI Agent 应用开发岗」为主体 + 叠加 FDE 交付能力** 的复合路线。核心不再是 Java，而是 Python + AI 应用层，Java 保留为加分项。

## 三、企业真实 JD 提炼（哪些是硬要求）

从上海AI实验室、联想、腾讯、智联等多份 2026 招聘 JD 交叉提炼的**共同硬技能**：

- ✅ **编程**：精通 Python（异步、工程化、模块封装）或 Java/Go；扎实算法与数据结构；生产级代码质量
- ✅ **LLM API 深度使用**：同步/异步调用、**流式输出（SSE）**、函数调用、多模态
- ✅ **Prompt 工程**：角色设定、CoT、少样本、格式约束、反幻觉优化
- ✅ **RAG 全链路**：文档加载、分块、Embedding、向量库、检索优化、重排
- ✅ **Agent 框架**：LangChain / **LangGraph**（工业界 90% 在用）
- ✅ **Tool Calling + MCP 协议**（2026 必学，工业级工具接入标准）
- ✅ **规划决策**：ReAct、Plan & Execute、Reflexion
- ✅ **记忆管理**：短期上下文、长期记忆、摘要复用
- ✅ **工程化**：FastAPI/Flask、向量库（Chroma/Milvus）、Docker、Git、可观测性、评测
- ➕ **加分**：多智能体、Agent 可观测性/评测体系、垂直场景（金融/法律/医疗/客服）、前端可视化

> 注：你问的 SSE 正是 JD 里"**流式输出**"这一条的底层实现——它是 AI Agent 应用开发的必学项，不是冷门知识。

## 四、12 周可执行学习路线（每周任务 + 资源 + 验收标准）

> 设计原则：**不做"所有技术全学一遍"**。以"应用开发岗 + FDE 交付"为目标，每阶段都有可验收的项目产出，最后汇成 FDE 风格作品集。

### 第 0 阶段｜基线切换（第 1 周）
- **任务**：补 Python 工程化（异步 asyncio、类型注解、模块封装）；熟悉 LLM API（豆包/DeepSeek/OpenAI 任选一，跑通同步/异步/流式/函数调用）
- **资源**：Python 官方教程、FastAPI 文档、所选 LLM 的 API 文档
- **验收**：能用 Python + FastAPI 写一个带**流式返回**的 `/chat` 接口（用 SSE 逐字输出）；会看 token 用量与 cost

### 阶段 1｜LLM 应用基础（第 2 周）
- **任务**：Prompt 工程全技能（角色/CoT/少样本/格式约束/反幻觉）；结构化输出（JSON Schema）；Function Calling 完整循环
- **资源**：OpenAI Function Calling 指南、Prompt 工程公开课
- **验收**：做一个"工具调用 Agent 雏形"——模型识别意图 → 调你自定义的工具 → 返回结构化结果

### 阶段 2｜RAG + 流式 + 工具调用（第 3–4 周）
- **任务**：RAG 全链路（加载/分块/Embedding/向量库/检索/重排/多模态）；MCP 协议原理与接入；SSE 生产化（分块、背压、断线重连）
- **资源**：LangChain RAG 官方教程、MCP 官方规范、Chroma/Milvus 文档
- **验收**：做一个**企业知识库问答 Agent**：答案带引用来源、能拒答、能标注"无依据"，接入 1 个 MCP 工具

### 阶段 3｜Agent 核心（第 5–6 周）
- **任务**：LangGraph 状态机与图；纯代码实现一个 **ReAct Agent**（不用框架）；Plan & Execute、Reflexion；记忆管理（短期/长期/摘要）
- **资源**：LangGraph 官方 Tutorial、ReAct 论文、Anthropic 多智能体研究博客
- **验收**：从零写一个能用工具、会规划、能自我修正的长任务 Agent；处理循环调用/任务跑偏

### 阶段 4｜生产化 + 评测 + 可观测（第 7–8 周）
- **任务**：Docker 部署、推理延迟优化、token 成本控制、缓存；Agent 全链路追踪与日志；**评估体系**（建评估集、定义指标、测引用准确率/无依据比例/拒答正确率）
- **资源**：LangSmith / Phoenix 可观测、Docker 教程、Agent 评测实践
- **验收**：把阶段 2–3 的 Agent 容器化部署，配好 trace + 评估集，能量化"改进前后"的指标

### 阶段 5｜多智能体 + 垂直场景 + 前端（第 9–10 周）
- **任务**：多 Agent 协作（AutoGen/CrewAI/LangGraph 实现角色分工、任务调度）；选一个垂直场景做深（**建议：供应链/客服**——你懂业务）；用 Streamlit/React 做 Agent 可视化交互（流式渲染、工具调用过程可视化）
- **资源**：CrewAI 文档、AutoGen 教程
- **验收**：做一个多 Agent 系统，能协同完成一个复合业务任务，前端能看到思考/工具调用过程

### 阶段 6｜FDE 交付闭环 + 求职冲刺（第 11–12 周）
- **任务**：选一个**真实流程**（内部支持队列/客服/文档审核任选），按 FDE 方式走完整闭环：**发现 → 一页范围 → 完整切片 → 评估集 → 小范围发布 → 记录证据**
- **资源**：AI FDE 学习路径（aifde.dev）、FDE 在线考试测评
- **验收**：产出 **1 个 FDE 风格作品集案例**：用户/工作流 → 范围与非目标 → 系统图（数据/权限/模型/工具/人工复核）→ 评估案例与失败分类 → 发布/监控/回退计划 → 结果证据 + 下一轮为什么这样改

## 五、FDE 风格作品集（求职核心竞争力）

普通作品集只丢 GitHub 链接，**FDE 作品集展示判断过程**。每个案例必须包含：
1. 观察到的用户与工作流（摩擦发生在哪一刻）
2. 第一版范围、非目标、约束
3. 数据/权限/模型/工具/人工复核如何连接的系统图
4. 评估案例、失败分类、质量门槛
5. 发布、监控、回退计划
6. 发布后结果证据 + 下一轮为什么这样改

**没有真实客户怎么办**：用自己的团队流程、公益组织或社区流程开始，诚实标注场景。展示发现笔记、范围化构建、评估、发布计划和观察到的使用，不必假装有企业级数据。

## 六、面试准备清单

**技术深挖**（连环追问你的 Agent 项目：技术选型→落地痛点→优化→效果）
- ReAct 原理、与其他决策框架区别、适用场景
- RAG 全流程优化、怎么降幻觉
- MCP 核心原理、与传统工具调用的区别
- Agent 长链路不稳定/循环调用/任务跑偏的解法
- 场景题：给垂直场景（如客服、供应链），现场设计 Agent 架构
- 流式/SSE 实现细节、token 成本控制

**FDE 场景题**（判断你是否真的懂"现场交付"）
- 如何选第一个客户问题？上线后谁负责可靠性？怎么做评估？客户出差比例？
- 讲一个被缩小/推迟/回退的上线案例
- 判断需求"是否真值得做"而不是一味迎合

**反问对方**：团队怎么选第一个客户问题、上线后谁负责可靠性、怎么评估、现场反馈怎么影响产品——能快速筛掉"挂 FDE 头衔的售前"岗位。

## 七、方向建议（针对你的情况）

1. **技能重心**：Python 优先（Agent 岗位硬要求），Java 降为加分项；若想发挥 Java 优势，可同时熟练 **Spring AI**（Java 生态的 LLM 框架）作为差异化卖点
2. **垂直场景**：你的**供应链/零售业务认知（苏宁背景）**是多智能体解决方案岗和 FDE 的核心壁垒——选业务 Agent 场景时优先往这靠
3. **作品集**：别堆"漂亮但连假数据的页面"，要"可观察的小部署"——这最能证明 FDE 能力
4. **注意**：FDE 通常涉及客户现场/出差。你目前人在德国法兰克福，若目标是中国或国内企业岗位，需提前确认岗位是驻场型还是可远程型，据此决定是否投递
